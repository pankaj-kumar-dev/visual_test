# INSPIRATION — INGAMANA
> ingamana.com — Digital development studio portfolio
> Extract: portfolio grid layout, visual-first navigation, studio personality through copy, project card UX

---

## WHAT INGAMANA DOES DIFFERENTLY

Ingamana builds trust through volume of shown work, not claims about work. The entire site is essentially one large proof-of-work grid. Study this not as a portfolio template, but for how to let product/work quality speak without a marketing layer.

⚠️ **Caveat:** This studio has Awwwards recognition. Per our extraction protocol, avoid copying anything optimized for judges. Extract structural and copy principles only — not visual spectacle elements.

---

## SPACING PHILOSOPHY

**Observation:** Card grid uses consistent gaps — whitespace is structural, not decorative.

- Project cards at ~560px width — large enough to read thumbnails, small enough to show many
- Consistent padding creates visual rhythm across 16+ projects
- No hero section stealing above-the-fold space — grid starts immediately
- Breathing room between cards prevents merge, keeps each project distinct

**Extract:** When your primary content IS the work (portfolio, marketplace, gallery), skip the hero and lead with the work. Consistent card spacing creates rhythm without requiring layout complexity.

---

## TYPOGRAPHY RHYTHM

**Observation:** Typography recedes to let project imagery lead.

- Project titles + year on cards — minimal metadata, no verbose descriptions
- Studio tagline short and direct: "We help brands, agencies & designers to make digital things happen"
- Personality injected through copy, not typography weight/size variation
- Likely monochromatic text (light on dark) to push visual contrast toward images

**Extract:** When visuals carry hierarchy, text should be a label system, not a hierarchy system. Minimal metadata per card is better than rich metadata that competes with the image.

---

## INTERACTION DENSITY

**Observation:** Everything is a card. Exploration model is browse-then-drill.

- Flat information architecture — project grid → project detail
- No mega-menus, no complex navigation
- Cards are the navigation
- Hover states likely the only interaction surface beyond clicks

**Extract:** When work is the product, flatten the IA. Grid → Detail is sufficient. Every level of navigation added between those two is friction.

---

## INFORMATION HIERARCHY

**Observation:** Studio bio section humanizes with deliberate copy choice.

- "Nice people. The kind we'd have over for dinner" — positioning statement that does personality work
- Recruitment call visible ("Are you a developer?") — studio is hiring, embedded naturally
- Client names (Sony, Nike, Honda, Adidas) provide tier signal without a dedicated "clients" section

**Extract:** Studio/team personality can be established in 1-2 lines if the copy is precise. Don't need an "About" page wall of text. Embed the personality in functional copy.

---

## EMOTIONAL TONE

**Observation:** Collaborative confidence — skilled but human.

- Not "award-winning agency" chest-thumping
- "Nice people" framing lowers the intimidation barrier for potential clients
- Work quality creates the confidence; copy creates the approachability

**Extract:** For service/studio sites, let work create confidence, let copy create approachability. Never reverse this — leading with self-praise before showing work reads as insecurity.

---

## TRUST PATTERNS

**Observation:** Trust through volume and recognizability.

- 16+ projects visible immediately — breadth = experience
- Client brand recognition (Nike, Sony) = peer validation without quotes
- Year labels on cards = longevity, active portfolio
- No testimonials on homepage — work is the testimonial

**Extract:** Strong portfolio trust pattern: show many real projects + recognize-able client names. Testimonials and case stats are supplementary, not primary. The work is the argument.

---

## MOTION PHILOSOPHY

**Observation:** Card-based layout implies hover states as primary motion surface.

- Likely: card lift/scale or overlay reveal on hover
- No need for scroll-triggered animations when content is a flat grid
- Performance matters — grid of WebP images should load fast; motion must not block this

**Extract:** For image-heavy grids, prioritize load speed over motion sophistication. A fast-loading grid with simple hover states beats a slow-loading grid with impressive animations.

---

## WHAT NOT TO EXTRACT

- The Awwwards-recognized visual spectacle elements — optimized for judges, not users
- Full-bleed project card grid for non-portfolio products — this layout only works when work = product
- "Nice people" phrasing — extract the principle (humanize with copy), not the line
- Minimal metadata per card — only works when imagery is self-explanatory; fails for abstract products
